## 3. Hostinger Directory Mapping

On Hostinger, the domain `gad-ams.me` maps to a **document root** under:

```
/home/u366424097/domains/gad-ams.me/
├── public_html/              ← Document root (what the browser sees)
│   ├── index.php             ← Vue SPA entry (generated by Vite plugin)
│   ├── assets/               ← Vite-built JS/CSS bundles
│   ├── images/               ← Static images
│   ├── api/                  ← Symlink or physical dir → CI4 public/
│   │   ├── .htaccess         ← CI4 rewrite rules
│   │   └── index.php         ← CI4 front controller
│   └── .htaccess             ← Master routing rules
└── backend/                  ← CodeIgniter 4 application code
    ├── app/
    ├── vendor/
    ├── writable/
    └── .env
```

### Key routing in `.htaccess` (document root):

```apache
# /api/* → routed to api/index.php (CodeIgniter 4)
# Everything else → index.php (Vue SPA)
```

This means the Vue SPA and the CI4 API share the same domain — no CORS issues.

## 4. CI/CD — GitHub Actions Workflows

There are **two separate, independent workflows**. A backend change never triggers the frontend workflow and vice versa (using `paths:` filters).

### 4.1 Frontend Deploy (`deploy-public-html.yml`)

```
Push to main (public_html/** changed)
        │
        ▼
┌─────────────────────────┐
│ 1. Checkout repo        │
│ 2. Setup Node 20        │
│ 3. npm ci               │
│ 4. npm run build        │ ← Vite builds to public_html/dist/
│ 5. Publish dist/ to     │
│    orphan `deploy` branch│ ← uses peaceiris/actions-gh-pages@v4
└─────────────────────────┘
        │
        ▼
 Hostinger Git (auto-deploy)
 pulls `deploy` branch
        │
        ▼
 Files land in public_html/
 on the server
```

**How it works:**
1. The GitHub Action builds the Vue app and pushes the **compiled output** (`dist/`) to an **orphan branch** called `deploy`
2. In **Hostinger hPanel → Git**, the `deploy` branch is connected to the domain's `public_html/` directory
3. Hostinger's Git integration **auto-pulls** whenever a new commit appears on the `deploy` branch
4. Result: the built assets (index.php, assets/, images/, .htaccess) appear in the live document root

**Secrets required:**
- `GITHUB_TOKEN` — auto-provided (needs `contents: write` permission)
- `VITE_API_BASE_URL` — optional, defaults to `https://gad-ams.me/api`
- `VITE_TURNSTILE_SITE_KEY` — Cloudflare Turnstile captcha key

**Trigger:** Push to `main` when `public_html/**` changes, or manual `workflow_dispatch`

---

### 4.2 Backend Deploy (`deploy-backend-ssh.yml`)

```
Push to main (backend/** changed)
        │
        ▼
┌───────────────────────────────┐
│ 1. Checkout repo              │
│ 2. Setup PHP 8.3 (intl, gd)  │
│ 3. composer install --no-dev  │
│ 4. rsync via SSH to Hostinger │ ← uses easingthemes/ssh-deploy@main
│    SOURCE: backend/           │
│    TARGET: /home/u366424097/  │
│      domains/gad-ams.me/      │
│      backend/                 │
└───────────────────────────────┘
```

**How it works:**
1. GitHub Action installs PHP dependencies with `composer install --no-dev --optimize-autoloader`
2. Deploys the entire `backend/` folder to the Hostinger server via **SSH rsync**
3. Files are synced directly to the server's `backend/` directory

**Secrets required:**
- `HOSTINGER_SSH_KEY` — Private SSH key for authentication
- `HOSTINGER_HOST` — Hostinger server IP/hostname
- `HOSTINGER_USER` — SSH username (e.g., `u366424097`)
- `HOSTINGER_PORT` — SSH port (Hostinger uses non-standard port)

**Trigger:** Push to `main` when `backend/**` changes, or manual `workflow_dispatch`

## 5. Build Process Details

### Vite Build (`npm run build`)

The build produces a `dist/` folder containing:

| Output | Source |
|--------|--------|
| `index.php` | Custom Vite plugin generates PHP wrapper around `index.html` for Facebook/Twitter OG meta tags (social sharing previews) |
| `assets/*.js` | Code-split Vue chunks (hashed filenames for cache busting) |
| `assets/*.css` | Tailwind-compiled CSS |
| `.htaccess` | Copied from `public/.htaccess` (Apache routing rules) |
| `api/` | Copied from `public/api/` (CI4 rewrite + symlink) |
| `images/` | Copied from `public/images/` |

> **Important:** The build deletes `index.html` and replaces it with `index.php` for the social bot meta-tag injection system. This is why the SPA fallback in `.htaccess` routes to `index.php`, not `index.html`.

## 8. Hostinger-Specific Configuration

### hPanel Git Setup
1. In hPanel → **Git** section, connect the GitHub repository
2. Set the branch to `deploy`
3. Set the target directory to `public_html/`
4. Enable **auto-deploy on push**

### SSH Access
1. In hPanel → **SSH Access**, enable SSH
2. Generate an SSH key pair
3. Add the public key to Hostinger
4. Store the private key in GitHub → **Settings → Secrets** as `HOSTINGER_SSH_KEY`
5. Note the host, user, and port for the other secrets

### PHP Configuration
- PHP version must be set to **8.3** in hPanel → PHP Configuration
- Required extensions: `intl`, `gd`, `curl`, `mbstring`, `json`

## 9. Known Issues & Fixes

### ERR_HTTP2_PROTOCOL_ERROR on JS assets
- **Cause:** Hostinger's CDN (hcdn) applies Brotli compression automatically. If `.htaccess` also has `mod_deflate` enabled, the double-compression creates a `Content-Length` mismatch in the HTTP/2 stream
- **Fix:** Remove `mod_deflate` from `.htaccess` — the CDN handles compression
- **File:** `public_html/public/.htaccess`

### Large bundle warning
- The main `index-*.js` bundle is ~624 KB (207 KB gzipped). Vite warns about this
- The app uses dynamic `import()` for all route-level views (code splitting is already active)
- The large chunk is primarily `vue`, `vue-router`, `axios`, and `chart.js`

### `index.html` vs `index.php`
- Vite's custom plugin deletes `index.html` after build and generates `index.php` instead
- This is intentional — `index.php` contains a PHP prelude that serves OG meta tags to social bots (Facebook, Twitter, etc.) for proper link previews
- The `.htaccess` SPA fallback routes to `index.php`, not `index.html`

## 10. Deployment Checklist

### To deploy frontend changes:
1. Make changes in `public_html/`
2. Commit and push to `main`
3. GitHub Action automatically builds and pushes to `deploy` branch
4. Hostinger auto-pulls the `deploy` branch
5. Verify at https://gad-ams.me

### To deploy backend changes:
1. Make changes in `backend/`
2. Commit and push to `main`
3. GitHub Action rsyncs to Hostinger via SSH
4. Verify API at https://gad-ams.me/api

### Manual deploy (emergency):
- **Frontend:** Run `workflow_dispatch` on `deploy-public-html.yml` from GitHub Actions tab
- **Backend:** Run `workflow_dispatch` on `deploy-backend-ssh.yml` from GitHub Actions tab
